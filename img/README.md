# img/，实景照片存放目录

把下载好的照片放进这里，然后在 `data/photos.js` 的 `items` 里加一条同 id 的记录，
并在 `CREDITS.md` 的清单里补一行。三处对得上才会通过校验。

## 命名规范

`景点id-序号.扩展名`，例如：

- `xxl-1.jpg`，西夏陵第 1 张
- `hbt-2.jpg`，海宝塔第 2 张
- `sdg-1.jpg`，水洞沟第 1 张

景点 id 就是 `data/yinchuan.js` 里每个景点的 `id` 字段（攻略卡链接用的也是它）。

## 尺寸与体积

- 长边建议 1600px，横构图（题图按 16:6 居中裁切，缩略图按 68:50 居中裁切）
- 单张压到 800 KB 以内；超过 `node test/credits.js` 会提示
- 全站照片合计建议 15 MB 以内，保证双击离线打开依然流畅
- 优先 `.jpg`；`.webp` 更小但老浏览器兼容性略差

## 授权

只放 CC0 或公有领域的图片。每一张都要在 `CREDITS.md` 里登记作者、协议、原始链接与获取日期。
`node test/credits.js` 会核对两边是否一致，也会检查有没有「放进了目录却没登记」的孤儿图片。

本目录下的说明文档不会被当成图片，不需要登记。

## 首页背景照片（可选）

除景点照片外，这里还可以放一张首页背景照片。做法只有两步：

1. 把图存进来，例如 `hero.jpg`（建议 1600×900、横构图，压到 300 KB 以内）；
2. 在 `data/photos.js` 里把 `hero: null` 换成一条登记（字段模板就在那行的注释里），
   并在 `CREDITS.md` 加一行。

放好之后 `node build-standalone.js`，单文件版会自动把它内联成 base64，不需要再改样式或脚本。
没登记时页面一次请求都不会发，不会在控制台留下 404。

背景是压到 11% 不透明度、底边淡出的氛围层。选图时注意两点，否则效果会打折：

- 别选主体在画面正中偏下的：那一带正好被白色内容卡片压住，等于白放。
- 别选高对比、深色天空的：压淡之后会变成一片脏灰，而不是「有照片」。

晨雾里的远山、逆光的河谷、大面积留白的沙丘这类低对比、上部有主体的图，投影效果最好。
