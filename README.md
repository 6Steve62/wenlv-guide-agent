# 文旅导览智能体 · 银川

给来宁夏银川的游客排线路的智能体。主界面是一个对话框：打开是欢迎区和输入框，直接说「玩三天，第一次来，喜欢人文历史，住新华街」，系统会把需求一次收齐，当场排好逐日行程；没说全的会追问，想改口再补一句。两种用法共用同一套排程引擎。

- 出发前做计划：输出逐日时间轴和一张按天分色的行程走向图。入口只有说话这一条。天数、熟悉程度、兴趣、节奏、范围、住宿，说得越清楚越好，没说全就逐项追问。原来的六步向导已从界面撤掉（`#wizard` 仍留在 DOM 里，供「已在路上」流程和验证脚本使用）。熟悉程度决定推荐口径：第一次来优先 5A/4A 招牌景区，2 天行程也排得到贺兰山国家森林公园；多次来把招牌权重下调，多排 3A 和未评级点位；本地人则优先小众点位。
- 已在路上：按当前位置、现在几点、今天去过哪些、今天玩到几点重排，输出行程、还能去哪、去不了的原因。首屏点「已在银川 · 从此刻重排」进入。

「听懂人话」和「排线路」是两层。前者由对话外壳完成，规则解析器作主路径，不联网、可单测，可选的大模型只替换这一层；后者是确定性引擎，同样的参数永远输出同样的行程，模型不参与。所以改口重排不会动摇「同参同果」。细节见第六节。

![首屏：左边主张与提要，右边自绘示意底图，下面横贯品类色标带与五行「本期可选」目录，输入行钉在视口下沿](验证截图-v14-首屏.png)

*首屏是一个正在印出来的地理志图版。标题不写死城市名，哪座城由顶栏题签交代；右边这张底图是内联 SVG，不是瓦片，也不是 SDK 渲染。*

*部分代码由 AI 辅助生成，范围与责任见文末《开发与责任》。*

行程走向图是自绘的矢量底图，黄河、贺兰山、湖泊湿地和建成区全部内联在 SVG 里，不请求瓦片、不接地图 SDK、不需要审图号，断网和双击打开时表现一致。图上的出发位置是一枚定位指针，上圆下尖的水滴，赭金色，旁边写着「行程起点」（做计划时）或「当前位置」（已经在路上时）。每天从指针尖端出发，末站再由虚线回到指针，一头一尾两道虚线就是当天的往返，行程因此闭合成环。把鼠标放到任意一段连线上（手机上点一下），会弹出这一段的直线与路网里程、自驾和公交骑行步行的门到门耗时，以及每种耗时由什么构成，例如「车程 32 分 + 停车 3 分」。详见 `地图接入方案.md`。

首页按这个顺序读：标题、题签（在哪儿）、一句提要（推荐线路，讲背景与看点，安排交通用餐停留）、一行品类统计、「本期可选」目录、直接说话。45 处景点分 11 类，默认只露前五类，点「展开全部 11 类」看全。十一类全铺开会把目录挤出首屏，也盖过了「直接说话」这件正事。

首屏背景是一层极淡的自绘山河，贺兰山脊、黄河水纹、日轮、飞鸟，同样是内联 SVG，没有图片文件。它留了一个可选的照片位：`data/photos.js` 里登记一张 CC0 实景照，照片就会以 11% 不透明度压在山河之上；没登记时页面一次请求都不发，控制台也不会留 404。政府文旅部门网站上的宣传图不在收录范围内，理由与口径见 `CREDITS.md`。

## 一、交付形式

纯 HTML + CSS + JavaScript 实现的静态站点，无框架、无构建步骤、无第三方依赖，默认零网络请求。顶栏有两个可选开关，大模型和外部检索，出厂都是关的，关着时整页一个请求都不发。

| 项 | 情况 |
|---|---|
| 作品形式 | Web 应用（静态站点） |
| 源码 | 完整可读，含逐段注释，见下方目录结构 |
| 是否需要安装 | 不需要。不需要 `npm install`，不需要打包工具 |
| 是否需要联网 | 不需要。断网状态下全部功能可用 |
| 外部资源 | 零。无 CDN、无字体外链、无地图 API 与瓦片服务、无图片外链 |
| 验证方式 | 双击 `index.html` 即可运行；`node test/all.js` 一键复跑全部验证脚本 |
| 评审复现 | 逐步走查清单见 `复现指南.md`，每步附应看到的结果，可逐字比对 |

若另在智能体平台上做过封装，那只是现场演示的通道，不影响本目录独立运行。

## 二、运行方式

### 方式一：直接打开（推荐）

双击项目根目录的 `index.html`，用浏览器打开即可。不需要启动服务，也不需要命令行。已验证在 `file://` 协议下可完整运行，控制台无报错。

### 方式二：本地静态服务器（可选）

若浏览器对本地文件有限制，或想以 `http://` 方式访问：

```bash
cd 文旅导览智能体
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

任意静态服务器均可，`npx serve`、IIS、Nginx 都行。本项目不含任何服务端逻辑。

### 方式三：单文件版（兜底）

若环境只能提供一个 HTML 文件、不提供同级目录资源（部分在线预览器如此），改用根目录的 `index-standalone.html`。它把全部 13 个脚本内联成一个 486 KB 的自包含文件，拷到任何地方单独打开都能完整运行，功能与多文件版一致。

这个文件是派生产物，由 `node build-standalone.js` 从源码生成，改完源码重跑一次即可；`node build-standalone.js --check` 可检查是否过期。主入口仍是 `index.html`，源码分文件、可读、可维护。

### 环境要求

| 项 | 要求 |
|---|---|
| 浏览器 | Chrome / Edge / Firefox / Safari 近两年版本（本项目在 Chrome 下验证） |
| 屏幕 | 桌面端设计，最窄适配 760px |
| Node.js | 只在复跑测试时需要（14 以上），运行应用本身不需要 |

代码规模：`index.html` 2180 行，`js/` 7 个文件 6163 行，`data/` 6 个文件 1324 行，合计 9667 行（不含测试）。其中 `intent.js` 615 行、`llm.js` 481 行、`search.js` 326 行、`dialogue.js` 608 行属于附加层，不改动引擎与界面渲染逻辑。

本仓库不含 `历史版本/`。那是 v1 到 v14 的 14 个整目录快照，约 59 MB，作用等同于 git 的历史记录，因此留在本地并写进 `.gitignore`。

架构上引擎与数据是分开的。`engine.js` 里没有任何城市专属常数，景点、住宿、周边、品类、照片、底图骨架都在 `data/` 下，换一座城市只需替换数据文件，代码一行不改；`map.js` 里同样没有银川专属常数，视框与缩放全部由数据推导。解析与排程也是分开的：`intent.js` 和 `dialogue.js` 只把自然语言收敛成结构化参数，最终仍走 `app.js` 的 `planWith` 入口调用同一引擎，所以话聊、已在路上流程、引擎直调三者产出逐字节一致，这一点由 `test/dialogue.js` 锁死。

## 五、数据说明与免责

- 景点门票、开放时间、停止入园时间、闭馆日采集自景区公开信息，以景区当日公示为准。
- 西夏陵免票政策按公开报道分时段呈现：3 月 1 日至 10 月 31 日每周一，11 月 1 日至次年 2 月 28 日每周一和周三，法定节假日除外，以景区当期公告为准。免票日不影响页面里的「人均门票」，引擎不知道读者哪天去，预算一律按全价口径累加。
- 车程由两点坐标按道路绕行系数估算，未接入实时路况。
- 配图有两种来源。一是 CC0 或公有领域的实景照片，逐张在 `data/photos.js` 登记作者、协议和原始链接；二是按视觉品类自绘的示意插画，仅用于视觉区分，不是实景照片，不作景观依据。
- 行程走向图是示意图，不是导航地图。底图地物（山脊、河道、湖面、建成区）为依据公开坐标手工绘制的近似轮廓，行程连线是直连弧线，不沿真实道路，密集点位做了不超过 20 像素的显示错开。它回答的是几天分别往哪个方向跑、彼此相距多远，不是哪个路口转弯。图上不绘制任何行政区划界线，也不声称具备导航精度。

## 六、智能体层：一句话排出行程

在确定性排程引擎之外，这一层把游客的一句话收敛成结构化参数，再交给引擎。承担这件事的是对话外壳，主路径是规则解析器，可选的大模型只替换解析这一步。

入口是这页图版。左边两行粗标题「把一座城走成一条线」和三段提要，右边一张自绘的银川示意底图，等高线山体、东侧黄河、建成区与湖泽，带图注和比例尺；下面横贯一条品类色标带，再往下是五行「本期可选」目录，末行是「已在银川 · 从此刻重排」。点任一行，或直接在底部输入行说话即可。整页做成应用壳，页面本身不滚，滚动只发生在内容区里，输入行钉在视口底部；空态时铺满整幅，会话态收窄到与正文同宽。行程结果（概览、走向图、时间轴）出现在消息下面、输入行上面，再长也压不下去。例如：

> 玩三天，第一次来，喜欢人文历史，住新华街

系统在半秒内解析出四个槽位（天数 3、熟悉程度 第一次来、偏好 人文历史、住宿 新华街），其余按默认口径补齐（节奏标准、范围全城、身份游客），当场调用与向导相同的排程入口生成结果页。一次没说全也没关系，系统只追问缺的那一项，比如没提住宿，答完即排，不用重来。

标题不写「银川」，是因为这句话讲的是方法，把一座城的点位排成一条能走的线，而不是讲这一份数据包。换掉 `data/` 那六个文件就是另一座城，引擎和界面一行都不用改；标题若跟着改一遍，说明它写错了层。具体是哪座城由顶栏题签交代，现在是「银川 · 图版 01」。同一把 API Key 也是这样：它换的是耳朵，把开放表达解析成槽位；不换地图，城市、点位、门票、开放时间全部来自本地数据包。填了 Key 不等于能搜全国，要加一座城，加的是 `data/`。这条边界在顶栏「模型」弹窗里写明了，`test/llm.js` 也锁着。

分层如下：

| 层 | 文件 | 职责 | 是否触碰排程 |
|---|---|---|---|
| 入口 UI | `index.html` + `js/dialogue.js` | 对话主界面（欢迎区、消息流、输入框）与槽位状态机 | 否 |
| 解析 | `js/intent.js` | 纯函数，把自由文本收敛成 `{days, role, prefs, pace, scope, lodgingId, visited, avoid}` | 否 |
| 共享入口 | `js/app.js` 的 `planWith` | 把结构化 state 展开成引擎入参 | 是（唯一入口） |
| 引擎 | `js/engine.js` + `data/*` | 排程、时间轴、自检 | 是 |

模型只做意图识别，不碰排程。默认主路径是 `intent.js` 里的规则解析器，同义词表加槽位启发式，不联网、不用第三方库、可单测；可选的大模型前置也只输出同一份槽位结构，排程永远由同一引擎完成。

话聊与「已在路上」走同一个 `planWith` 入口，输入相同的结构化参数，引擎输出逐字节一致。`test/dialogue.js`（20 项）锁死单句、分步、不限偏好三种对话路径与表单产出一致，`test/chat-ui.js`（41 项）锁对话界面的思考块、逐字打印、输入区吸底与结果逐块印出。

解析不出明确意图或槽位始终凑不齐时，消息里会明说「没太听懂」并给出示例，对话本身带逐项追问，不会卡死或给出假结果。

解析器里没有城市专属常数：景点名、住宿名、偏好词全部经 `ctx` 注入，换一座城市只换 `data/`，解析器一行不改（`test/intent.js` 91 项，含「换 ctx 即换城市」用例）。

大模型前置默认关闭。在顶栏「模型」里填入自己的 API Key 并启用后，`js/llm.js` 会先用模型把开放表达解析成同一份槽位结构，再与规则解析器的结果合并。三条边界：只补空，不改已经认出的槽位；只出槽位，不出事实也不出文案，门票、开放时间、车程都不经过它，回显句在本地拼；任何失败静默回落，超时 2.6 秒、CORS、非 JSON、字段越界都退回规则解析器。默认关闭时页面零网络请求，整页确定性快照不受影响。预置智谱 GLM-4-Flash、硅基流动 Qwen2.5-7B、百度 ERNIE-Speed 三个长期免费端点，另有按量计费的 DeepSeek（`deepseek-flash`，会自动关掉它的思考模式），也可填任何 OpenAI 兼容网关。`test/llm.js` 75 项锁住这些边界。

外部检索同样默认关闭，单独一个开关。在顶栏「检索」里填入 Tavily 的 Key 并启用后，`js/search.js` 只在句子里命中时效词（临时闭园、活动、天气、限流、调价等）时去查一次，把最多 3 条原文链接作为旁注摆在回答上面。三条边界：只在数据包答不了的地方查，门票、开放时间、路线照旧走本地；只摆原文不让模型转述，请求里 `include_answer:false`，条目是标题、摘要、原文链接；不参与排程，旁注说今天闭园，行程也一个字不改。默认关闭时零网络请求，超时 3.5 秒或报错就写一行「没查到」，正文照常。`test/search.js` 56 项锁住判据、回落与渲染。

检索为什么不塞进模型的「服务商」下拉：那一栏是 `POST {base}/chat/completions` 加 `messages`，属于对话补全；检索是 `POST {base}` 加 `query`，返回网页摘要。协议、载荷、回包都不一样，混在一栏里填了也只会得到一个假开关。

![检索旁注：最多三条原文链接，挂在用户气泡下面、思考块上面，链接可点开原文](验证截图-v14-检索旁注.png)

这样分层的好处是把「理解人话」和「排线路」拆开：前者可以不断升级，接更强模型、扩同义词；后者保持确定性、可验证、可审计。引擎正确性已由 22 个脚本 921 项断言固定，对话层只是换了个入口。

## 七、换一张首页背景图（可选）

首页背景默认只有自绘山河。想换成实景照片，三步：

1. 图片放进 `img/hero.jpg`，横构图，压到 300 KB 以内（单文件版会把图片 base64 内联，体积约 1.33 倍）；
2. 在 `data/photos.js` 末尾把 `hero: null` 改成一条登记，`file / subject / author / license / source / fetched / modified` 七个字段缺一不可；
3. 跑 `node test/credits.js` 核对授权与文件，再跑 `node build-standalone.js` 重打包单文件版。

授权只收 CC0 与公有领域，口径与排除清单见 `CREDITS.md`。自己拍的照片是最干净的来源：`author` 填本人姓名，`license` 填 `PD-self` 或 `CC0`，`source` 填 `self:` 开头的一句拍摄说明。自摄照片没有网页链接可填，脚本和 `CREDITS.md` 都认这个前缀。

第 3 步不能省。多文件版改完 `photos.js` 就会显示背景，但单文件版是在打包时才把图片内联进去的，不重打包就还是旧版，`test/all.js` 也会报「已过期」。

## 开发与责任

这个项目由人与 AI 助手对话完成，范围如下。

`index.html` 的页面结构、样式与内联 SVG 底图，`js/` 下的排程引擎、地图渲染、意图解析、大模型适配与检索旁注，`test/` 下的验证脚本，以及各份文档的初稿，都是与 AI 助手逐轮对话生成并反复修改的。查资料、跑测试、做无头浏览器截图核对这些工作也由 AI 完成。

我做的是判断和把关这几件事：

- 需求与取舍。做什么、不做什么，例如地图不接第三方 SDK，考虑的是合规与断网可用；撤掉表单向导改成对话；模型只接在「听懂」这一层；检索只做旁注，不进结果。这些都是我定的，AI 负责实现并说明代价。
- 审核与验收。每版改动都逐项看过实际页面与测试输出，不对就退回重做。`node test/all.js` 的 921 项断言是我要求的门槛，不通过不算完成。
- 事实与数据。景点名单、门票、开放时间、坐标、免票政策这类内容，由我核对公开来源后录入，AI 不负责这部分。文中的量化指标（生成耗时、断言条数、校验项数）都是可现场复算的工程指标。
- 合规边界。图片只收 CC0 与公有领域，地图不接瓦片、不画行政界线，代码里不放任何密钥，这几条由我把关，并且写成了测试。

没有做过的部分也说明一下：我没有做过用户调研，所以不写满意度，也不写留存率。代码里可能还有未发现的缺陷，`node test/all.js` 和 `复现指南.md` 就是留给人复核的入口。
